# Glossary

The Yocto and Qualcomm terms this layer's documentation uses, each with the source it comes from.

| Term | Definition |
| --- | --- |
| Adreno | Qualcomm's GPU family; its firmware and the kgsl driver are packaged per SoC. Appears in meta-qcom's `conf/layer.conf`. |
| bbappend | A `.bbappend` file: an addition to a recipe that lives in another layer. It changes that recipe without copying it; the recipe it extends has the same name. Described in [Yocto terms: Append Files](https://docs.yoctoproject.org/ref-manual/terms.html#term-Append-Files). |
| BitBake | The build tool of the OpenEmbedded build system: it parses the metadata (recipes, classes, configuration) and schedules and runs the tasks that fetch, build and package software. Described in [Yocto terms: BitBake](https://docs.yoctoproject.org/ref-manual/terms.html#term-BitBake). |
| boot binaries (`BOOTBINARIES`), NHLOS | The prebuilt firmware bundle a Qualcomm board boots with, delivered as a signed archive of bootloader stages, partition tables and related images; NHLOS is the name meta-qcom's firmware recipes use for that bundle. Appears in meta-qcom's `recipes-bsp/firmware/firmware-qcom-nhlos.inc` and `recipes-bsp/firmware-boot/firmware-qcom-boot-common.inc`. |
| boot image (bootimg), mkbootimg, skales | An Android-style boot image bundles kernel, ramdisk and command line in one file; `mkbootimg` builds it, and skales is the CodeLinaro tool set that ships it. Appears in meta-qcom's `recipes-devtools/skales/skales_git.bb`. |
| CamX firmware (`camxfirmware`) | Camera firmware for Qualcomm's camera framework, packaged per SoC. Appears in meta-qcom's `conf/machine/iq-x7181-evk.conf`. |
| CDT, configuration data table | A small binary the boot firmware reads to identify the board variant; `QCOM_CDT_FILE` names it. Appears in meta-qcom's `recipes-bsp/firmware-boot/firmware-qcom-cdt-qcs6490.bb`. |
| class (`.bbclass`) | A file of shared build logic that recipes pull in with `inherit`; the `kernel`, `packagegroup` and `image` classes are examples. Described in [Yocto terms: Classes](https://docs.yoctoproject.org/ref-manual/terms.html#term-Classes). |
| defconfig | A kernel or U-Boot default configuration file, selected by name; `.cfg` fragments are merged on top of it. Kconfig is the kernel's configuration language the options are written in. Described in [KBUILD_DEFCONFIG](https://docs.yoctoproject.org/ref-manual/variables.html#term-KBUILD_DEFCONFIG). |
| device tree | The hardware description the kernel boots with, compiled from source into a `.dtb` file per board; `KERNEL_DEVICETREE` names which. Described in [KERNEL_DEVICETREE](https://docs.yoctoproject.org/ref-manual/variables.html#term-KERNEL_DEVICETREE). |
| distro | The distribution policy layer of a build, selected by `DISTRO`. `nodistro` is the built-in empty policy; `qcom-distro` is the policy meta-qcom-distro provides. Described in [DISTRO](https://docs.yoctoproject.org/ref-manual/variables.html#term-DISTRO); `nodistro` appears in meta-qcom's `ci/base.yml`. |
| eMMC | The on-board flash storage most of these boards boot from; partition file sets are named for it. Appears in meta-qcom's `conf/machine/rb1-core-kit.conf`. |
| flashable image, qcomflash | The package of partition images and programming files a Qualcomm board is flashed with; meta-qcom's `qcomflash` image type assembles it. Appears in meta-qcom's `classes-recipe/image_types_qcom.bbclass`. |
| Hexagon DSP: ADSP, CDSP | Hexagon is Qualcomm's DSP architecture; the ADSP (audio) and CDSP (compute) are the two DSP subsystems the firmware packages target. Appears in meta-qcom's `recipes-bsp/packagegroups/` recipes and its `hexagon-dsp-binaries-*` recipes. |
| image types: wic, vfat, bmap | The output formats an image is written in, listed in `IMAGE_FSTYPES`: `wic` is a partitioned disk image, `vfat` a FAT filesystem image, `.bmap` a block map that lets a flashing tool skip empty blocks. Described in [IMAGE_FSTYPES](https://docs.yoctoproject.org/ref-manual/variables.html#term-IMAGE_FSTYPES). |
| IMSDK, QAIRT | Qualcomm software packages the machine configurations recommend; IMSDK provides GStreamer plugins, as the UNO Q kernel configuration fragment notes, and the Dragon Q6A recommends `qairt-sdk-hexagon-v68`. Appears in [conf/machine/radxa-dragon-q6a.conf](../conf/machine/radxa-dragon-q6a.conf), [recipes-kernel/linux/linux-arduino/configs/arduino.cfg](../recipes-kernel/linux/linux-arduino/configs/arduino.cfg) and meta-qcom's `recipes-multimedia/imsdk/gst-plugins-imsdk-common.inc`. |
| kas, kas fragment | kas is the tool the CI uses to check out the layers a build needs and run BitBake; a kas fragment is one of the small YAML files under `ci/` it composes into that build. Described in [kas project configuration](https://kas.readthedocs.io/en/latest/userguide/project-configuration.html). |
| kernel command line | The text of options the kernel is booted with; `KERNEL_CMDLINE_EXTRA` appends to it. Appears in meta-qcom's `classes/linux-qcom-bootimg.bbclass`. |
| layer | A directory of related metadata (recipes, classes, configuration) that BitBake loads as a unit. This repository is one layer; meta-qcom and OpenEmbedded-Core are the two it depends on. `bblayers.conf` lists the layers of a build. Described in [Yocto terms: Layer](https://docs.yoctoproject.org/ref-manual/terms.html#term-Layer). |
| LPASS (`LPASSCC`) | A Qualcomm component whose kernel option, `CONFIG_SM_LPASSCC_6115`, the UNO Q kernel configuration fragment enables. Appears in [recipes-kernel/linux/linux-arduino/configs/arduino.cfg](../recipes-kernel/linux/linux-arduino/configs/arduino.cfg) and meta-qcom's `recipes-kernel/linux/linux-yocto-6.18/bsp/qcom-armv8a/qcom-sm8450.cfg`. |
| machine | The target board, selected by `MACHINE`; its `conf/machine/<name>.conf` file sets the board-specific variables. Override tokens scoped to a machine apply only when it is selected. Described in [MACHINE](https://docs.yoctoproject.org/ref-manual/variables.html#term-MACHINE) and [MACHINEOVERRIDES](https://docs.yoctoproject.org/ref-manual/variables.html#term-MACHINEOVERRIDES). |
| OpenEmbedded, OpenEmbedded-Core | The build system BitBake drives, and the core layer of recipes and classes every build starts from. Described in [Yocto terms: OpenEmbedded-Core](https://docs.yoctoproject.org/ref-manual/terms.html#term-OpenEmbedded-Core-OE-Core). |
| package group | A recipe that builds no software; it names a set of packages to install together, so an image or a machine can pull them in by one name. Described in [Yocto terms: Package Groups](https://docs.yoctoproject.org/ref-manual/terms.html#term-Package-Groups). |
| partition table tool (ptool) | Qualcomm's tool that turns a partition description into the partition files the flashable image carries. Appears in meta-qcom's `recipes-bsp/partition/qcom-ptool-native.bb`. |
| PARTLABEL | A way to name the root partition on the kernel command line by its GPT label instead of a device path. Appears in meta-qcom's `conf/machine/qcom-armv7a.conf`. |
| qbootctl | A helper that marks a boot as successful to the boot firmware, which otherwise switches to the other slot and fails to boot. Appears in [conf/machine/uno-q.conf](../conf/machine/uno-q.conf). |
| QUP (qupv3) | A Qualcomm component with firmware of its own; the Dragon Q6A package group recommends that firmware package, named with `qupv3`. Appears in [recipes-bsp/packagegroups/packagegroup-radxa-dragon-q6a.bb](../recipes-bsp/packagegroups/packagegroup-radxa-dragon-q6a.bb) and meta-qcom's `recipes-bsp/packagegroups/packagegroup-rb3gen2.bb`. |
| rawprogram XML | The `rawprogram<n>.xml` files inside a flashable image that tell the flashing tool which image goes to which partition. Appears in meta-qcom's `classes-recipe/image_types_qcom.bbclass`. |
| Realtek RTL8169 | The Ethernet controller on the Radxa Dragon Q6A; a kernel configuration fragment enables its driver. Appears in [recipes-kernel/linux/linux-qcom-next_git.bbappend](../recipes-kernel/linux/linux-qcom-next_git.bbappend). |
| recipe | A `.bb` file: the instructions to fetch, configure, build and package one piece of software. Described in [Yocto terms: Recipe](https://docs.yoctoproject.org/ref-manual/terms.html#term-Recipe). |
| root filesystem (rootfs) | The filesystem image the kernel mounts as `/`; `root=` on the kernel command line names where it is. Described in [Yocto terms: Image](https://docs.yoctoproject.org/ref-manual/terms.html#term-Image). |
| semgrep, repolinter, patchreview, buildstats | CI tools: a code scanner, a repository conventions checker, OpenEmbedded's patch header review, and the build statistics post-processor. Appears in [ci/README.md](../ci/README.md) and [.github/workflows/README.md](../.github/workflows/README.md). |
| shared state (sstate) | The cache of already built task outputs that lets a build reuse work instead of redoing it. Described in [Shared state cache](https://docs.yoctoproject.org/overview-manual/concepts.html#shared-state-cache). |
| SPI NOR (spinor) | A flash chip attached over SPI that some boards boot from; the flashable image carries a separate partition set for it. Appears in meta-qcom's `classes-recipe/image_types_qcom.bbclass`. |
| sysfs, userspace, metapackage, allarch | General Linux and packaging terms: the kernel's `/sys` interface; programs outside the kernel; a package that only pulls in others; a recipe whose output is the same for every architecture. Described in [allarch class](https://docs.yoctoproject.org/ref-manual/classes.html#allarch). |
| Thundercomm, Radxa, Arduino UNO Q (unoq, imola) | Board vendors and boards: Thundercomm builds the RB1 kit whose DSP binaries the UNO Q reuses; Radxa makes the Dragon Q6A; imola is the Arduino UNO Q's internal board name. Appears in [conf/machine/uno-q.conf](../conf/machine/uno-q.conf) and [recipes-bsp/packagegroups/packagegroup-uno-q.bb](../recipes-bsp/packagegroups/packagegroup-uno-q.bb). |
| U-Boot | The open-source bootloader this layer builds for the Arduino UNO Q; `UBOOT_CONFIG` selects its configuration. Described in [UBOOT_CONFIG](https://docs.yoctoproject.org/ref-manual/variables.html#term-UBOOT_CONFIG). |
| upstream, upstreamed | The original project a piece of software or a layer comes from; a change is upstreamed when it is accepted there rather than kept as a local patch. Described in [Yocto terms: Upstream](https://docs.yoctoproject.org/ref-manual/terms.html#term-Upstream). |
| usbhost, usbgadget, alsa | Machine feature names: USB host and USB device (gadget) roles, and ALSA audio support. Described in [Machine features](https://docs.yoctoproject.org/ref-manual/features.html#machine-features). |
| XBL, UEFI, ABL, chainloading | Stages of the Qualcomm boot firmware that runs before the kernel. On the Radxa Dragon Q6A the vendor-managed SPI NOR carries XBL and UEFI, and boot runs PBL, then XBL, then UEFI, which finds the EFI system partition; on the Arduino UNO Q, U-Boot is chainloaded from ABL as an Android-style boot image. Appears in [conf/machine/radxa-dragon-q6a.conf](../conf/machine/radxa-dragon-q6a.conf) and meta-qcom's `conf/machine/include/qcom-common.inc` and `recipes-bsp/u-boot/u-boot_%.bbappend`. |
| Yocto release names: wrynose, scarthgap, kirkstone | Yocto Project releases are named; a layer branch of the same name tracks that release. Wrynose is the current one for this layer, scarthgap and kirkstone are the older long-term-support releases it also has branches for. Described in [Yocto release process](https://docs.yoctoproject.org/ref-manual/release-process.html). |
